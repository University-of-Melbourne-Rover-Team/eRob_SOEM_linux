# URT EtherCAT Maindevice
CANopen over EtherCAT (CoE) maindevice for the rover's EtherCAT network.  
This URT EtherCAT maindevice uses the SOEM library to handle EtherCAT service and process data exchange.  
https://github.com/openethercatsociety/soem  
This implementation is adapted from the eRob_SOEM_Linux repository from ZeroErr.  
https://github.com/ZeroErrControl/eRob_SOEM_linux  
  
`./demo/` contains multiple independent programs which implement demonstrations of CiA-402 control modes.  
`./src/` contains the main program that runs on the URT rover's maindevice.  
> **Note:** This program works with Ubuntu Linux with real-time kernel capabilities. Compatability with other OS not been tested.

### URT maindevice usage
1. **Check the EtherCAT port network interface is configured correctly:**  

First run:  
```bash
ip link
```
... to obtain network interface string of EtherCAT port (Usually `enx...` or `enp...`).  

In `/src/config.h`, check the `DEFAULT_IF_NAME` string matches the network interface of EtherCAT port OR run the executable with the `if_name` string as command line input (step 3).  

To verify linkstate, run:
```bash
ethtool <if_name>
```
If the EtherCAT cable is connected, it should output `Link detected: yes`

2. **Build executables:**
```bash
mkdir build  
cd build  
cmake ..  
make  
```

Note this builds the `src/main` executable and the `demo/` executables.  
To build only the `src/main`, configure cmake:  
```bash
mkdir build  
cd build  
cmake -DBUILD_DEMOS=OFF ..  
make  
```

3. **Run executable:**  

Option 1: With default network interface:  
```bash
sudo ./build/src/main
```

Option 2: With another network interface:  
```bash
sudo ./build/src/main <if_name>
```

### URT maindevice configuration
The maindevice is configured at compile time in `/src/config.h`. All values are `constexpr` in the `config` namespace. Invalid values are caught at compile time by `static_assert`.

#### EtherCAT master configuration
- `DEFAULT_IF_NAME`: default network interface string of the EtherCAT port.
- `CYCLE_TIME_US`: process data exchange (PDO) period in us.
- `SYNC0_CYCLE_NS`: Distributed clock SYNC0 event period in ns.
- `SYNC0_SHIFT_NS`: Offset of SYNC0 event from cycle boundary in ns.

#### Real-time process and thread configuration
- `PROCESS_CPU_CORES`: CPU cores the process is pinned to (ideally isolated cores, and memory is locked).
- `RT_THREAD_PRIORITY`: `SCHED_FIFO` priority (1–99, higher runs first) of the real-time EtherCAT loop thread.
- `CHECK_THREAD_PRIORITY`: `SCHED_FIFO` priority of the bus monitoring/recovery thread (`ecat_check`). Must be below the RT thread.
- `THREAD_STACK_SIZE`: Stack size in bytes for the RT and check threads.

The main thread stays on the default `SCHED_OTHER` policy.

#### Bus monitoring (`ecat_check` thread)
- `CHECK_PERIOD_US`: Polling period of the check thread in us.
- `WKC_ERROR_THRESHOLD`: Consecutive working counter errors before slave states are checked and recovery starts.
- `WKC_REPORT_INTERVAL`: Working counter warning is printed every N polls.
- `EC_TIMEOUTMON`: Timeout in µs for slave reconfiguration and recovery.

#### Fieldbus and motors configuration
- `MAX_MOTORS`: Maximum number of motors allowed on the bus.
- `MOTOR_MODES`: CiA 402 mode of operation for each motor, in bus order (entry 0 = slave 1). Supported: `MODE_CSP` (cyclic synchronous position) and `MODE_CSV` (cyclic synchronous velocity).

`MOTOR_MODES` must have exactly one entry per slave on the bus otherwise program will exit.  

#### Drive internal limits
Written to every motor via SDO during startup.
- `MAX_VELOCITY_DEG`: Maximum motor speed (degrees/s).
- `MAX_ACCELERATION_DEG`: Maximum motor acceleration/deceleration (degrees/s^2).
- `QUICK_STOP_DECEL_DEG`: Deceleration (degrees/s^2) used for quick stop (in the case of fault/emergency).


#### CSP trajectory profile
CSP motors follow a trapezoidal profile generated by the maindevice every cycle (`src/trajectory.cpp`).
- `CSP_PROFILE_VELOCITY_DEG`: Cruise velocity of a CSP move (degrees/s).
- `CSP_PROFILE_ACCEL_DEG`: Acceleration and deceleration of a CSP move (degrees/s^2).

## eRob Demo Usage
### Build executables
```bash
mkdir build  
cd build  
cmake -DBUILD_DEMOS=ON ..  
make  
```

### Running demo:

1. CSV mode:
```bash
sudo ./build/demo/eRob_CSV
```

2. Launch the position subscriber (PP):
```bash
sudo ./build/demo/eRob_PP_subscriber
python3 src/erob_ros/src/eCoder_fake.py
```

3. Launch the position subscriber (CSP):
```bash
sudo ./build/demo/eRob_CSP_subscriber
python3 src/erob_ros/src/eCoder_fake.py
``` 

4. Launch the cyclic synchronous position mode (CSP):
```bash
sudo ./build/demo/eRob_CSP
``` 

5. Launch the profile torque mode (PT):
In this mode, we can control the torque of the servo motor and have added PDO mapping to obtain the position, speed, torque, and status word of the servo motor. 

```bash
sudo ./build/demo/eRob_PT
``` 
If you want to consult the object dictionary, you can run the following command and then run `sudo ./build/test/linux/slaveinfo <ethercat_device> -map` to view the object dictionary.


6. Launch the cyclic synchronous torque mode (CST):
In this mode, we can control the torque of the servo motor and have added PDO mapping to obtain the position, speed, torque, and status word of the servo motor. 

```bash
sudo ./build/demo/eRob_CST
``` 
If you want to consult the object dictionary, you can run the following command and then run `sudo ./build/test/linux/slaveinfo <ethercat_device> -map` to view the object dictionary.

## Recommendations for EtherCAT Open-Source Master Users  

1. **Use a Real-Time Kernel System**  
   Ensure your operating system has a real-time kernel to guarantee consistent and precise communication.

2. **Isolate CPU Cores**  
   Perform CPU isolation to dedicate specific cores to EtherCAT processes, reducing interruptions and improving stability.

3. **Troubleshooting OP State Issues**  
   - Failure to enter OP state may be caused by errors in the **object dictionary mapping** or improper configuration of **DC (Distributed Clock) mode**.  
   - **eRob** only supports **DC mode**, and proper configuration of DC mode is crucial for system synchronization and precision.

4. **Read Mode-Specific Instructions**  
   Before using each mode, read the relevant operational instructions to ensure correct configuration and usage.

5. **Use the Official eRob Upper Computer Software**  
   eRob provides official upper computer software. Mastering the built-in **oscilloscope tool** will allow you to quickly locate issues with the EtherCAT master.

6. **Capture and Analyze EtherCAT Data**  
   Use packet capture tools to analyze EtherCAT output and log information to identify errors.
